# GemStar State Storage

GemStar stores local state in files and SQLite. Runtime memory is temporary only; commands rebuild state from disk when they start.

## Source Of Truth

| Area | Location | Role |
| --- | --- | --- |
| Paper trading ledger | `alerts/ledger.jsonl` | Source of truth for simulated cash/positions. |
| Current trade snapshot | `artifacts/current/trade_status.json` and `.md` | Latest readable account/target/decision snapshot. |
| Notification history | `alerts/live.jsonl` | Append-only local alert history. |
| Research/run history | `state.db` | SQLite run and step records. |
| Run artifacts | `artifacts/<run_id>/` | Leaderboard, reports, verdicts, drafts, manifests. |
| Market data cache | `data/raw/*.parquet` | Tushare/cache data used by run/trade. |

## Paper Trading Ledger

`alerts/ledger.jsonl` is the authoritative paper-trading record. Each line is one confirmed simulated execution. `gemstar trade` reads this file on startup and reconstructs:

- cash
- current positions
- average cost / last marked price
- T+1 flags used by paper-trading checks

The current position is not stored as a separate database row today. If `alerts/ledger.jsonl` is deleted, GemStar treats the next `trade` run as a fresh paper account with empty positions and the configured capital.

## Current Snapshot

`artifacts/current/trade_status.json` and `artifacts/current/trade_status.md` are convenience snapshots for humans, Feishu, skills, scripts, and dashboards.

They are not the source of truth. They can be regenerated by running:

```bash
gemstar trade --once
```

## Run State

`state.db` tracks research pipeline runs and steps. `artifacts/<run_id>/` stores larger artifacts such as leaderboards, reports, validations, and backtests.

`state.db` does not currently store paper positions.

## Reset Semantics

`gemstar reset trade`:

- backs up `alerts/ledger.jsonl`
- backs up `artifacts/current/trade_status.json`
- backs up `artifacts/current/trade_status.md`
- deletes those files
- keeps `alerts/live.jsonl`
- keeps `state.db`
- keeps `artifacts/<run_id>/`
- keeps `data/raw`

`gemstar reset trade --include-alerts` additionally backs up and deletes `alerts/live.jsonl`.

`gemstar reset all`:

- includes `reset trade --include-alerts`
- backs up `state.db`
- deletes run records from `state.db`
- deletes `artifacts/<run_id>/`
- keeps `data/raw`

Use `--dry-run` to preview and `--keep N` with `reset all` to keep the most recent runs.

## Design Note

The current JSONL ledger is simple, append-only, easy to inspect, and easy to back up. It is suitable for paper trading.

If GemStar evolves toward long-running production or broker-connected trading, the paper ledger should move into SQLite tables such as `paper_trades` and `paper_account_snapshots`, with JSONL kept only as an export or backup format.
