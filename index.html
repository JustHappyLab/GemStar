// Features

核心能力

从数据采集到策略评审，全自动闭环

⚡

自动调度

Auto Scheduling

交易日感知，自动跳过非交易日。后台 scheduler 运行，失败自动重试，最多 3 次。

🤖

多 Agent 协作

Multi-Agent

8 个专业角色分工协作，4 种 LLM 后端可切换。通过 YAML 配置即可更换 Provider。

📊

因子健康监控

Factor Health

基于 IC/IR 的因子健康度分析，异常自动降级，确保策略信号质量。

🔬

回测引擎

Backtesting

真实 A 股约束：T+1、涨跌停、滑点。与聚宽验证 NAV 差异 0.0000%。

📡

实时信号监控

Live Radar

盘中 30s/盘外 300s 轮询，自动识别买卖信号。涨跌停/T+1 约束，Telegram 中文通知。

📒

持仓跟踪账本

Paper Ledger

JSONL 追加式账本，跨日持仓感知。信号不再是重复"买入"，而是持仓感知的增持/减持。

// Multi-Agent

8 个专业角色协作

每个角色专注一个领域，通过数据流串联，形成完整研究闭环

感知层
📡
event_scanner api
统计检测器扫描异动：财报惊喜、成交量异常、动量突变
scan_events
🌍
macro_analyst api
20 日市场统计 → 判断 regime：bullish / bearish / volatile / defensive
analyze_market
SignalEvent[] + MarketRegime →
研究层
🔬
research_analyst api
综合市场信号 + 因子健康度，生成研究 ticket（假设 + 因子关联）
generate_tickets
🏗️
strategy_architect api
从 research ticket 草拟策略 YAML，输出可验证的策略配置
draft_strategy
⛏️
factor_miner api
LLM 自动发现新 alpha 因子表达式，IC 验证后注册入池
discover_factors
ResearchTicket[] → Strategy YAML → Backtest
评审层
⚖️
reviewer api
解读回测结果，生成评审意见：解释 + 风险 + 置信度（纯建议，无决策权）
review_verdict
ReviewNotes (advisory) → Daily Report
工程层
💻
engineer claude_code 需批准
编写或修改策略代码，操作文件系统。仅 CLI 类 provider 可用
write_code fix_bug
🔧
bugfix claude_code 需批准
紧急修复：分析错误 → 定位代码 → 最小化修复 → 验证
fix_bug
// Feedback Loop

闭环反馈机制

多层反馈确保策略质量和系统自愈

🔄 策略生成循环
Iterative Generation Loop
1 generate_tickets — 从市场上下文生成研究假设
↓
2 draft_strategy — 草拟策略 YAML
↓
3 validate + backtest — 验证并回测
↓
4 judge — 5 道硬性关卡评估
↓
↻ rejected → 重新生成 tickets，循环直到收集足够 candidate
🛡️ 故障自愈 FSM
Incident Self-Healing — 7 States
DETECTED 异常发现
CLASSIFIED 分类：data / LLM / backtest / quality
RETRYING 自动重试，失败可回到 CLASSIFIED
DEGRADED 降级运行，跳过 LLM 阶段
MANUAL 需要人工介入
ENGINEERING 创建 bugfix 任务
RESOLVED 问题解决
↻ RETRYING → CLASSIFIED 可循环，实现自愈
🚦 策略评审关卡
5 Hard Gates — 全部通过才能成为 candidate
Sharpe
≥ 1.0
Calmar
≥ 0.8
Max Drawdown
≥ -30%
Trades
≥ 100
Segment IR Std
≤ 0.5
